@pocket thanks for many questions.

1) What is "stochastic adversarial blending"?
As @andy refered in this post, we can build a model which can distinguish train or test data.
We use that prediction ( adversarial validation ) when blending.
The process is as follows,

Sample data with a sampling ratio by using adversarial validation as a sampling weight.
Optimize the weights with train prediction.
Iterate 1~2 process to get converged weights.

This technique propelled our score about 0.0002.

2) Did you all share the features for each of your models?
Some were shared, others were not.

3) What features did you use for the final blend?
For the final blend, we did not use any features.
Attached image shows the features used in each model.
( Cardinal numbers were allocated in each feature. )

4) Were you looking at the CV score to tune your blend?
Yes. We monitored both CV and Public LB.
We submitted the predictions which have nice score in CV and public LB, both.

5) Did you all choose the same cv-split for the blend?
Actually at first we tried to keep same cv-split.
But after some experiments of stacking we did not care cv-split any more.
( Stacking tended to overfit. CV >> LB. So we decided to use only blending. )

Solution

My Solutions are End to End CNN and RNN.
Purpose is getting time series features from tables.
Prev, ins, pos_cash bbureu, credit tables have days columns.
So I wanna get *** time series features ***.

I sort tables by days(e.g. instalment is DAYS_INSTALMENT)
apply convolution or rnn to tables

apply dense layer to 3

RNN: Public/Private LB: 0.795/0.791
