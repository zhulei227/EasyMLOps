Architecture

My model has a simple structure with EdgeConv and Transformer connected. I aimed to combine EdgeConv and Transformers in my model to efficiently gather information. GNNs were employed to capture local neighborhood information, while Transformers were used to collect global context, ensuring a comprehensive understanding of the data. This simple model achieves a public score of 0.9628 points and a private score of 0.9633 points as a single model.

Static edge selection for GNN

In the original paper, edges are calculated in each layer dynamically, but this edge selection is not differentiable and cannot be trained. This still works well for the segmentation task in the original paper, as points in the same segment are trained to be close in the latent space. However, the situation is different in this task, so I did not think it would make sense to dynamically select edges. Therefore, the edge selection used in EdgeConv is calculated at the input.

Loss function

VMFLoss is a good and stable loss function, but θ is in the form of cos:

VMFLoss = -κ*cos(θ) + C(κ)


(where θ is the angle between the ground truth and the prediction and κ is the length of the 3D prediction). On the other hand, the metric of this competition is the angle θ itself. To minimise θ itself, I defined the loss function as follows:

MyLoss = -θ - κ*cos(θ) + C(κ)


This simple modification resulted in a 0.005👍 gain compared to VMFLoss.

Sequence Bucketing

In transformers, computational complexity is proportional to the square of the sequence length, making it essential to reduce the sequence length. As a result, it is effective to group data with similar sequence lengths and create mini-batches. This approach speeds up computation and further decreases the GPU memory usage, allowing for the utilization of larger mini-batche size.

It is easy to implement by changing collate_fn in the DataLoader.

def collate_fn(graphs, split_list=[0.8, 1.0]):
    graphs = [g for g in graphs if g.n_pulses > 1]
    graphs.sort(key=lambda x: x.n_pulses)
    batch_list = []
    for minp, maxp in zip([0]+split_list[:-1], split_list):
        min_idx = int(minp*len(graphs))
        max_idx = int(maxp*len(graphs))
        this_graphs = graphs[min_idx:max_idx]
        this_batch = Batch.from_data_list(this_graphs)
        batch_list.append(this_batch)
    return batch_list


Note that even if gradients are calculated individually for each length-biased mini-mini-batch in the batch_list, the negative effects can be mitigated by updating the weights collectively afterwards.

Data loading

Because the data was huge and it was difficult to put everything in memory, I tried to load one batch per epoch. The pseudo code is shown below.

class IceCubeDataset(Dataset):
    def reset_batch(self):
        # get next batch id
        self.this_batch_id = self.get_next_batch_id()
        # read batch for next batch id
        self.this_batch = pd.read_parquet(f"{BATCH_DIR}/batch_{self.this_batch_id}.parquet")
        # filter meta with next batch id
        self.this_meta = self.meta[self.meta.batch_id == self.this_batch_id]

Model parameters

This is some information about base models which are used for stacking. 4 Layters, 6M parameters seems to be smaller than other top solutions.

Depth of EdgeConv+Transformer block layer: 3 or 4
Embedding dimension: 256
Used sequence length (train): 200 to 500
Used sequence length (inference): 6000
With/without global features
Number of parameters: 6M
Parameters used in kNN for GNN: x,y,z or x,y,z,time
Training time: 10 to 14 hours/epoch (on 2x titan RTX)
Inference time: 30 minutes/5 batches ( on Kaggle notebook)

Inference time is relatively slow due to the use of 6000 sequences.

Stacking

The framework for stacking was primarily based on the original base model. The main difference was that the model was replaced with a 3-layer MLP. Through stacking, an improvement of +0.003 was achieved.
