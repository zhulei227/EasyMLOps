# Machine Learning Yearning 方法论速览（概览与阅读地图）

> 《Machine Learning Yearning》（Andrew Ng 著，2018）是一本讲"如何做机器学习项目的策略决策"的工程指南：不教算法原理，而是教如何**组织数据集、设计评估指标、诊断模型瓶颈、决定下一步优化方向**。本目录将其方法论提炼为可操作的中文速查笔记，并与 easymlops 的工具与 playbooks 建立映射。引用请注明原书出处；原书官网 mlyearning.org 可免费获取电子书（许可证 CC BY-NC-SA，禁止商用）。

## 核心思想（一页版）

1. **先诊断约束，再动手改**。大多数时间浪费在"猜哪条路有效"上；应该用评估体系和误差分析先回答"什么在限制系统性能"，再决定投入方向。
2. **评估先行**。数据集划分和评估指标要在写训练代码之前确定，且必须与业务最终目标对齐；否则迭代方向本身就是错的。
3. **正交化**。把系统调整拆成互相独立、各自只影响一个环节的旋钮（训练集表现 → 开发集表现 → 测试集表现 → 真实世界表现），一次只拧一个旋钮。
4. **数据质量 > 架构微调**。标注质量和数据代表性决定上限；"更好的数据胜过更好的算法"。训练数据必须真实代表线上环境。
5. **快速搭建第一个能跑的系统，然后靠误差分析迭代**。不要一上来就过度设计，先有一个端到端基线，才有诊断的载体。
6. **偏差/方差/数据不匹配三分诊断**。现代 ML 的误差归因不止两类，还需判断训练集与开发集分布是否一致（见 04 文档）。
7. **多阶段流水线的瓶颈定位**。端到端模型和分组件系统各有取舍，复杂系统要用分部件误差分析找最弱环节（见 05 文档）。

## 与本项目（easymlops）的映射

| MLY 概念 | easymlops/本 skill 中的落点 |
|---------|---------------------------|
| 快速搭建第一个系统 | playbooks/00_framework.md ③ 基线模型 |
| 误差分析（按类别统计错误） | playbooks 各篇"迭代路径"；用 `transform` 拿到概率后按业务切片分析 |
| 单一数字评估指标 | `easymlops.table.utils` 的 PR/ROC 阈值工具选业务阈值；业务侧约定主指标（如 KS/召回@精确率约束） |
| 学习曲线诊断 | 自绘：逐步扩大 `x_train` 子集，对比训练/验证误差（sklearn `learning_curve` 或手写循环） |
| 与人类水平对比 | 业务专家可达到的水平作为 bayes error 估计；风控场景=资深核保/理赔员的判断 |
| 训练/测试分布不一致 | playbooks 中"按时间切分样本"的 OOT 思路；分布漂移用 PSI 自算（`PSIFilter` 实测不稳，见 SKILL.md 陷阱 16） |
| 数据不匹配的应对 | 外补 imblearn 重采样、人工合成样本；playbooks/05 反欺诈 |
| 分部件误差分析 | 表格+NLP 双路 pipeline（playbooks/02、10）：分别测每条支路的准确率，定位弱环节 |
| 端到端 vs 分组件 | easymlops 的 `Parallel` 多路 + 手工特征工程属于"分组件"路线；数据量大时可对比端到端深度模型 |
