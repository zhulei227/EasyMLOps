# 训练/测试分布不一致与数据不匹配（MLY 原书 Part 7，第 36-43 章）

> 本笔记用自有语言概括原书方法论要点，供 skill 使用时快速查阅；细节以原书为准。

## 1. 何时应 train/test 用不同分布（第 36 章）

- 现代项目的常态：训练数据"容易获得但不够代表性"，dev/test 只能从目标场景（真实线上流量）拿。
- 原则：**dev/test 必须来自目标分布**；训练集可以混入非目标分布的数据来扩充规模。宁可训练集与 dev 分布不同，也不要让 dev/test 偏离线上。
- easymlops 落点：风控场景"上线后回流样本"作为 dev/test（按时间切分），历史存量数据作训练集（playbooks/00 ①）。

## 2. 该不该用上全部数据（第 37-39 章）

### 数据选择（第 37 章）

- 训练集与 dev 分布不一致时，为训练集增量的数据需评估：加入后 dev 表现变好就用，变差就不用——用实验说话，不靠直觉。
- 经验：**与目标分布接近的数据**优先；相关性弱但量大的数据谨慎加入。

### 是否纳入不一致数据（第 38 章）

- 判断标准：不一致数据是否会引入"学到虚假相关"的风险。若它只贡献多样性的信息（如不同口音的语音），利大于弊；若它带有与标签无关但与场景绑定的系统性差异（光照、渠道统计口径），可能有害。

### 数据加权（第 39 章）

- 必须混用不同分布数据时，可对"与 dev 分布一致的数据"加权、不一致数据降权，让有效分布向目标场景倾斜。
- 原书建议先把"纯目标分布数据"直接训练的版本作为基线，再验证加权的必要性。
- 落点：lightgbm 支持样本权重（`weight`），easymlops 模型 pipe 未直接透出时需在 pipeline 外自行处理（外补缺口，见 playbooks 工具缺口总表思路）。

## 3. 三分诊断：偏差、方差、数据不匹配（第 40-41 章）

训练集 ≠ dev 分布时，两数比较会失真，需要**多造一个切分**：

```
训练误差（Train）
训练集中"与 dev 同分布的子集"上的误差（Train-dev）
dev 误差
```

| 观察 | 诊断 | 处理 |
|------|------|------|
| Train-dev ≫ Train | **数据不匹配**（模型没见过 dev 类型的样本） | 转数据不匹配应对（见下） |
| Train-dev ≈ Train，dev ≫ Train-dev | 方差 | 加数据/正则（见 [03 文档](./03_bias_variance_learning_curves.md)） |
| Train 高 | 偏差 | 提容量/改特征 |
| Train-dev 与 dev 都高且接近 | 方差不严重 | 混合分布可接受，聚焦其他问题 |

## 4. 处理数据不匹配（第 42-43 章）

### 分析误差 + 理解差距

- 人工查看 dev 错误样本，找出"训练集里没有/表现不同"的模式（渠道差异、口径差异、时间演化等）。
- 把 dev 特有的模式想办法在训练数据中体现出来。

### 人工数据合成（第 43 章）

- **合成数据的风险**：容易只合成出目标分布的一个狭窄子集，模型学到"合成痕迹"而非真实特征（原书语音/图像场景的典型教训）。合成前先问：合成数据能否覆盖目标分布的全空间？
- 落点：
  - 反欺诈/反洗钱少数类合成 → imblearn SMOTE（外补，playbooks/05）
  - 类别组合稀疏 → `CrossCategoryWithNumber` 等交叉特征部分缓解
  - 时间演化 → OOT 分段训练、滑动窗口重训

## 5. OOT/漂移监控 checklist（结合本 skill）

- [ ] dev/test 取自目标分布（上线后回流、近期时段）
- [ ] 三分诊断数据齐备：Train / Train-dev / dev 三组误差
- [ ] 混用异分布数据前，先跑"纯目标分布"基线
- [ ] 上线后定期算 PSI（`PSIFilter` 实测不稳，建议自算 PSI 或用 toad）监控特征与分数漂移
- [ ] 合成数据需验证覆盖度：合成样本在真实 dev 上的表现是否与真实样本一致
