## 1. 偏差与方差：两大误差来源（第 20-23 章）

用三个数定位问题（在 dev/test 同分布前提下）：

| 量 | 定义 |
|----|------|
| 训练误差 | 模型在训练集上的错误率 |
| 开发误差 | 模型在 dev set 上的错误率 |
| 最优误差（bayes error） | 问题本身能达到的最低错误率，**不是 0**（噪声、信息不完备决定下限） |

- **偏差（可避免偏差）≈ 训练误差 − 最优误差**：模型在训练数据上就没做好 → 欠拟合。
- **方差 ≈ 开发误差 − 训练误差**：训练与开发之间的差距 → 过拟合。
- 修正后的决策规则（比旧教材"永远权衡 bias/variance"更可操作）：

```
训练误差高、接近 dev 误差  → 先降偏差
训练误差低、dev 误差明显高 → 先降方差
两者都高                  → 先降偏差（模型还没学起来，方差问题无从谈起）
```

## 2. 应对手段清单（第 25-27 章）

### 降低可避免偏差

- 更大容量/更多迭代的模型（LGBM 加深度、加 boosting 轮数、更换更表达力强的模型）
- 更好的特征（新的信息来源、更有效的编码——easymlops 特征工程四板斧，见 SKILL.md 脚本表）
- 减少模型正则化（如 lightgbm 的 `min_data_in_leaf`/`lambda_l1` 调小）
- **先做训练集误差分析**（第 26 章）：模型在训练集上犯什么错，往往和 dev 上同类——先让训练误差降下来

### 降低方差

- 更多训练数据（最稳的一招）
- 正则化（weight decay、早停、L1/L2、lightgbm 的叶子数/学习率/`feature_fraction`）
- 特征选择（`IVFilter`/`LGBMEmbed` 等降维去噪）
- 模型融合（`HillClimbingStackingRegression`，或多个 `Parallel` 支路平均）
- 早停（用 dev 指标早停）

## 3. 学习曲线（第 28-32 章）

- **画法**：横轴 = 训练样本量（取 10%、25%、50%、100%...），纵轴 = 误差；同时画训练误差与 dev 误差两条线。
- 解读：
  - **高偏差**：训练误差高，且随样本增加趋于平稳、两条线收敛到同一高位 → 加数据没用，要提容量/改特征。
  - **高方差**：两条线之间有明显 gap，dev 误差随样本增加仍在下降 → 加数据有用，或加正则。
  - 最优误差不为零时，两条曲线渐近线应与最优误差线对照，而非 0。

## 4. 与人类水平表现对比（第 33-35 章）

- **为什么要比**：人类水平是最优误差最方便的估计，尤其在没有理论 bayes error 的业务问题（风控、医学判读）上。它决定了"可避免偏差"的分母。
- **怎么定义**：取"普通人类 / 熟练者 / 专家小组"中与目标对齐的那一档——如果目标是让专家满意，就用专家水平；如果目标是替代平均人工，就用平均水平。
- **超越人类之后**（第 35 章）：一旦模型超过人类水平，可避免偏差变得难以估计，偏差/方差诊断的指导性下降；此时应更依赖与业务口径对齐的指标、线上 A/B 与稳定性监控。
- 落点（风控场景）：资深核保员/理赔查勘员的判定准确率 ≈ 人类水平；用 IV/KS 与专家抽样一致率双轨评估。

## 5. 快速决策表

| 现象 | 诊断 | 首选动作 |
|------|------|---------|
| 训练误差 ≈ 最优误差，dev 高 | 方差 | 加数据 / 正则 / 特征选择 / 融合 |
| 训练误差远高于最优误差 | 偏差 | 提容量 / 换更强特征 / 降低正则 |
| 训练误差高且 dev 同高 | 高偏差 | 同上（先别加数据） |
| 学习曲线收敛到高位 | 高偏差 | 提容量/改特征 |
| 学习曲线 gap 大且 dev 仍在降 | 高方差 | 加数据/正则 |
| 加数据后 dev 不再降 | 已到偏差主导 | 转向提容量或特征工程 |
